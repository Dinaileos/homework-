## Схема наследования

В проекте используется два абстрактных базиса (интерфейса) и множественное наследование для техники.

### Базовые абстракции (Inventory.hpp)
*   **`InventoryItem`** — базовый интерфейс для всего, что стоит на балансе. Содержит чисто виртуальные методы `GetId()`, `GetName()` и `GetScore()` (по умолчанию возвращает 0 для вещей).
*   **`EnergyConsumer`** — базовый интерфейс для техники и вещей, потребляющих энергию. Содержит чисто виртуальный метод `GetDailyEnergy()`.

### Иерархия классов (Множественное наследование)

есть 2 базовых абстрактных класса InventoryItem и EnergyCOnsumet, от первого наследуются все что может храниться на балансе 
Scooter, EBike, Bike, Monocycle, Dock ,Helmet, 
от второго все что имеет энергию и весь транспорт(у некоторых она нулевая)
Scooter, EBike, Bike , Monocycle, Dock
### Иерархия исключений (Errors.hpp)
*   **`FleetError`** : `public std::runtime_error` (Общий базис для всех ошибок).
    *   **`InspectionError`** : `public FleetError` (Отказ техосмотра).
    *   **`CommandError`** : `public FleetError` (Ошибки ввода, неизвестный тип).
    *   **`RegistryError`** : `public FleetError` (Переполнение журнала).

unique_ptr — единоличное владение новой единицей техники до техосмотра. Если возникает отказ (исключение), объект уничтожается, а парк не меняется. При успехе владение передаётся в парк.
shared_ptr — парк хранит принятые единицы техники в vector<shared_ptr<InventoryItem>>.
weak_ptr — используется для «витрины»: выбранной напоказ позиции парка («самоката дня»).
